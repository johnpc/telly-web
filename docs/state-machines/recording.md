| Recording row      | `RecordingStatus` SCHEDULED → RECORDING → DONE · FAILED, SCHEDULED → FAILED (missed), and web-only RECORDING → STOPPING → DONE for the user's Stop (the row says it is closing its file, so the library keeps no optimistic `stoppedIds` copy — Android's listed known gap); every edge is a Dexie update guarded by the row's CURRENT status inside one `modify` transaction (`and(status === from)`) and reports whether it happened, so a cancel racing a start, a double finish or a finish on a deleted row can never rewrite a row | `src/features/recording/recordingStatus.ts`, transitions in `src/features/recording/recordingStoreTransitions.ts` (rows written only through `src/features/recording/recordingStore.ts`) | explicit | `src/features/recording/recordingStore.test.ts`, `src/features/recording/recordingEngine.test.ts`, `src/features/recording/recordingScheduler.test.ts` |

Web honesties (see the decisions log): captures live in the Origin Private
File System inside the browser profile and count against its storage quota;
the scheduler ticks only while the tab is open and visible (no alarm
wakeups, as on Android — the settings pane says so); a tab closed mid-capture
leaves the row RECORDING until the next start finalizes it from the file size.
