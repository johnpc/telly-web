# State machines — core (shared by every slice)

Rows for the machines that live under `src/core/` and are rendered or leased
by several slices at once. Same columns as `docs/state-machines.md`; the
first two are web-only (Android's input queue and Compose lifetimes give the
guarantee for free), the third names the refcount Android's
`SharedPlayerEngine` / `RemindersHub` share without a row.

| Machine               | States                                                                                                                                                                                                                                                                                                                                                                                               | Owner                                                                                                                                                                                                                                                                                                                                                                                       | Status   | Tests                                                                                                                             |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------- |
| PIN entry             | `PinEntryState` Typing(wheel, typed) · Submitted(pin) — the 4th digit OR OK commits exactly once; `Submitted` is deaf to every key but BACK until the host's promise settles (accept → the prompt unmounts, reject → Typing with blank wheels / an empty field). Web-only row: Android has one `SettingsScreenPinEntry` composable                                                                   | `src/core/ui/pinEntry.ts` (transitions), `src/core/ui/pinEntryStore.ts` (submission lifecycle), hook `src/core/ui/usePinEntry.ts`; rendered by `src/features/playback/gate/PinPromptScreen.tsx`, `src/features/panel/PinPrompt.tsx`, `src/features/groups/PinEntryScreen.tsx`, `src/features/settings/SettingsPinScreen.tsx`, `src/features/settings/SettingsPinKeyboardScreen.tsx`         | explicit | `src/core/ui/pinEntry.test.ts`, `src/core/ui/usePinEntry.test.tsx`                                                                |
| Startup key hold      | `KeyHold` Holding(keys) · Replaying(remaining) · Live — keys pressed before a screen can act are held, then replayed through the router ONE PER COMMIT; losing readiness re-opens the hold. Used by the guide (until the first rows), fullscreen playback (until the first channel) and search (while results are pending; only a DOWN from the bar opens its hold). Web-only: Android's input queue | `src/core/input/keyQueue.ts`, hooks `src/core/input/useKeyQueue.ts`; readiness fed by `src/features/guide/GuideBodyScreen.tsx`, `src/features/playback/usePlaybackController.ts`, `src/features/search/useDeferredDown.ts`                                                                                                                                                                  | explicit | `src/core/input/keyQueue.test.tsx`, `src/features/search/useDeferredDown.test.ts`                                                 |
| Shared resource lease | `SharedState` Free · Starting(holders) · Held(holders, resource) · Stopping — ONE refcount for every shared thing: the live engine, the reminders ticker, the DVR scheduler (its `Starting` is the async recovery sweep; a release during it cancels the start, so there is never a second scheduler) and the auto-backup watcher; a lease releases exactly once, so the count cannot go negative    | `src/core/state/sharedResource.ts` (+ `src/core/state/subscriberLease.ts` for `useSyncExternalStore` sources); leased by `src/core/player/sharedPlayerEngine.ts`, `src/core/player/usePlayerEngine.ts`, `src/features/reminders/remindersHub.ts`, `src/features/recording/recordingRuntime.ts`, `src/features/settings/backup/autoBackupEngine.ts`, `src/features/vod/vodPlaybackHolder.ts` | explicit | `src/core/state/sharedResource.test.ts`, `src/core/player/sharedPlayerEngine.test.ts`, `src/core/player/usePlayerEngine.test.tsx` |
| Engine release grace  | None · Pending(lease, timer) — the last external lease leaving the live engine arms a 400 ms grace lease; a screen taking over inside the window adopts the SAME engine (seamless guide ↔ fullscreen hand-over, since web routes never overlap), otherwise the timer frees it                                                                                                                        | `src/core/player/sharedPlayerEngine.ts`                                                                                                                                                                                                                                                                                                                                                     | explicit | `src/core/player/sharedPlayerEngine.test.ts`                                                                                      |
